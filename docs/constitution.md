# Arcadian Rush 헌법

상태: 리뷰 전  
날짜: 2026-11-13

한 판의 권한은 서버에 있다. 브라우저는 입력을 보내고 스냅샷을 그린다. 이 문서가 잠기기 전에는 게임 구현을 시작하지 않는다. 구현 계획은 잠긴 뒤에 슬라이스마다 쓴다.

이 헌법이 원칙이다. 메시지, 수치, 틱 순서는 [계약](specs/00-contract.md)이 정한다. 슬라이스 문서가 계약과 어긋나면 계약을 따른다.

## 확정된 원칙

1. 브라우저는 표시기다. 서버 권위로 쓰는 값은 서버 계산으로만 바뀐다.
2. 한 판은 웹소켓 하나다. 그 연결이 붙어 있는 함수 인스턴스의 메모리가 플레이어, 적, 투사체, 경험치, 공격력을 가진다.
3. 브라우저가 보낼 수 있는 게임 입력은 이동 의도, 업그레이드 번호, 일시정지, 재개다. 연결을 열 때의 `hello`는 토큰을 전달한다.
4. 수신한 JSON에서 스키마 밖의 필드는 제거한다. 체력, 공격력, 연사, 경험치, 레벨, 좌표를 상태에 덮어쓰는 경로는 없다.
5. 연결이 끊기면 그 판은 끝난다. 브라우저가 만든 이어하기 데이터는 받지 않는다. 재접속은 새 토큰이 있을 때만 새 판이다.
6. 공식 기록은 서버가 Neon에 끝낸 행의 생존 시간, 처치 수, 레벨이다. 화면의 숫자는 기록이 아니다.
7. 규칙 수치와 난수는 서버 모듈에만 둔다. 클라이언트 번들로 들어가지 않는다.
8. 1차 한 판은 Vercel Hobby의 함수 한도 안에서 서버가 스스로 끝낸다.
9. 이동을 자동으로 보내는 봇은 막지 않는다. 서버가 강제하는 것은 이동 속도 상한과 입력 간격 상한이다.

`hello`, 일시정지, 재개는 권한을 브라우저에 넘기지 않는다. 멈추고 다시 흐르는 것도 서버 페이즈다.

## 스택

| 역할 | 결정 |
| --- | --- |
| 앱 | Next.js App Router, TypeScript, Node.js 런타임 |
| 배포 | Vercel. 웹소켓은 Fluid Compute가 켜진 Functions |
| 화면 | Canvas 2D. 조이스틱, HUD, 레벨업 카드, 결과는 React |
| 입력 | 모바일 가상 조이스틱. 데스크톱 키보드. 호버에만 있는 조작은 없다 |
| 한 판 | `@vercel/functions` 3.10.0 이상의 `upgradeWebSocket` |
| 기록 | Neon Postgres. Vercel Marketplace 연결. `DATABASE_URL`은 서버만 읽는다 |
| 규칙 | `src/server` 아래 모듈. 파일 첫 줄은 `import "server-only"` |

Neon을 고른 이유는 서버 연결 문자열만 주입되기 때문이다. 브라우저용 공개 URL과 공개 키를 번들에 넣는 구성을 쓰지 않는다.

## 권한

```text
브라우저
  보냄: hello, 이동 의도, 업그레이드 번호, 일시정지, 재개
  그림: 서버 스냅샷

Next.js 웹소켓
  한 연결이 한 함수 인스턴스에 고정된다
  공격력, 체력, 적, 투사체, 판정, 난수, 레벨업 후보
  속도 상한, 입력 간격, 후보 번호 검사

Neon
  슬라이스 5부터 연결
  토큰 1회용 행과, 서버가 직접 쓴 종료 기록
  위치와 체력과 적 목록은 쓰지 않는다
```

Vercel은 새 웹소켓을 같은 인스턴스로 보낸다고 보장하지 않는다. 그래서 메모리만으로 이어하기를 만들지 않는다. 토큰을 발급한 인스턴스와 소켓을 받은 인스턴스가 다를 수 있으므로, 공식 모드의 1회용 검사는 Neon 행의 상태 전이로 한다. 그 행은 판정 상태가 아니다.

슬라이스 5 전의 메모리 저장소는 같은 프로세스 안에서만 1회용을 지킨다. 그 저장소의 종료는 공식 기록이 아니다. 공개 기록 모드는 Neon 저장소에서만 켠다.

## 위협

| 막아야 하는 일 | 규칙 |
| --- | --- |
| 메모리나 세이브에서 공격력, 체력, 연사, 경험치를 고침 | 그 값은 서버 메모리에만 있고 저장하지 않는다. 입력 스키마에 없다 |
| 브라우저가 레벨업 후보를 만듦 | 후보는 서버 난수로만 만든다. 클라이언트는 번호만 보낸다 |
| 화면의 가짜 숫자가 기록이 됨 | Neon에 쓰는 함수는 서버 저장소뿐이다. 점수 업로드 라우트는 없다 |
| 토큰 재사용, 추측 | 추측 불가능한 토큰, 짧은 만료, 1회 활성화 |
| 끊긴 판을 브라우저 데이터로 이어 함 | 재개 메시지 타입이 없다. 끊기면 종료다 |

폐기한 안: 브라우저 메모리를 RSA로 암호화하는 방법. 게임 루프가 값을 쓰려면 브라우저가 암호를 풀 수 있어야 하고, 그때 키도 브라우저에 있다. 키를 가진 쪽은 값을 바꾼 뒤 다시 암호화할 수 있다. Next.js를 쓰는 이유는 `DATABASE_URL`을 브라우저 번들 밖에 두기 위해서다.

## 플랫폼 한도

2026-11-13에 Vercel 문서를 기준으로 했다.

- Fluid Compute에서 Hobby 함수의 기본 시간과 최대 시간은 300초다.
- Pro와 Enterprise의 일반 최대는 800초다. 1800초는 지정 런타임의 연장 베타다.
- 웹소켓은 모든 플랜에서 Functions로 제공되고, 함수가 최대 시간에 닿으면 연결이 닫힌다.
- 연결 하나는 그 연결을 받은 인스턴스에 고정된다.
- Next.js에는 웹소켓 업그레이드 API가 없고, `upgradeWebSocket`이 그 경로다.

출처:

- <https://vercel.com/docs/functions/configuring-functions/duration>
- <https://vercel.com/docs/functions/limitations>
- <https://vercel.com/docs/functions/websockets>

1차 런의 벽시계 예산은 270초다. 나머지 30초는 종료 기록과 마지막 스냅샷의 여유다. 일시정지는 시뮬레이션 시간만 멈추고 벽시계는 계속 간다. 15분 런은 800초를 넘으므로 일반 Pro 한도 밖에 있다. 30분 런은 1800초 연장 베타의 천장과 같다. 둘 다 1차 범위 밖이다.

## 1차 범위

장르는 자동 공격, 이동만 조작, 경험치 레벨업, 최대 3지선다 성장이다.

슬라이스 순서:

1. [조작](specs/01-control.md)
2. [전투](specs/02-combat.md)
3. [성장](specs/03-growth.md)
4. [한 판의 끝](specs/04-run-end.md)
5. [공식 기록](specs/05-records.md)

콘텐츠 규모는 캐릭터 1, 무기 1, 맵 1, 적 3종, 업그레이드 6종, 도형과 단색이다. 이 규모와 [계약의 수치 표](specs/00-contract.md)는 인수인계에서 제안된 내용을 테스트할 수 있게 바꾼 기준안이다. 사용자가 항목별로 확정하지 않았다. 리뷰에서 숫자를 바꾸면 구현 계획보다 수치 표를 먼저 고친다.

1차 밖에 두는 것:

- 계정, 이름, 로그인
- 무기 추가, 진화, 보스
- 아트 파이프라인, 오디오
- 15분과 30분 런
- 사람인지 봇인지 구분
- 클라이언트 위치 예측
- 매 프레임 데이터베이스 쓰기
- RSA 메모리 암호화

## 잠금

리뷰에서 이 헌법과 스펙을 받아들이면 각 문서의 상태 줄을 `잠김`으로 바꾼다. 그 다음에만 해당 슬라이스의 구현 계획을 쓴다. 잠긴 뒤의 수치 변경도 계약의 표를 먼저 고치고 코드를 고친다.

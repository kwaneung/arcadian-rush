# 01 조작

상태: 잠김.

## 목적

서버가 발급한 토큰으로 한 판을 열고, 조이스틱과 키보드의 이동 의도만으로 서버 위의 플레이어를 움직인다. 화면은 그 스냅샷을 그린다.

## 입력

- `POST /api/runs`와 소켓 `hello`
- `move`
- 포인터 조이스틱과 WASD, 방향키
- 계약의 메모리 저장소

`pause`, `resume`, `choose`는 파서가 받지만 이 슬라이스의 `apply`는 상태를 바꾸지 않는다.

## 규칙

- 권한, 토큰, 속도, 입력 간격, 카메라, 색, 조이스틱 배치는 계약을 따른다.
- 이 슬라이스의 틱은 입력 창 확인과 플레이어 이동만 한다. 스폰, 공격, 경험치, 일시정지, 제한 시간 종료는 하지 않는다.
- 일시정지 버튼은 보이지만 비활성이다. 이름도 `일시정지`다.
- HUD에는 체력, 경험치, 생존 시각이 있다. 값은 스냅샷이다.
- 시작 전이거나 연결이 실패하면 Canvas에 로컬 플레이어를 만들지 않는다.
- 토큰은 페이지 메모리에만 둔다.

## 완료 조건

자동 테스트:

1. 유한하지 않은 `move`는 `null`이고 직전 의도가 유지된다.
2. 의도 `(3, 4)`는 길이 1의 벡터가 된다. 등급 0에서 한 틱의 이동 거리는 140 * 0.05다.
3. `move`에 체력 필드를 함께 넣어도 파서 결과에 그 필드가 없고, 틱 뒤 체력은 100이다.
4. 직전 1000ms에 `move`를 20개 받아들였으면 21번째는 의도를 바꾸지 않는다.
5. 활성화에 성공한 토큰의 두 번째 `activate`는 `reject`다. 만료 시각이 지난 토큰도 `reject`다.
6. 같은 주소 해시로 `issued_at > now - 60000`인 발급이 5개면 다음 `issue`는 `rate`이고 판 id가 생기지 않는다. `issued_at == now - 60000`인 발급은 그 개수에 넣지 않는다.
7. `hello`가 아닌 프레임만 온 채 열린 시각에서 5000ms가 지나면 닫힘 코드는 4002다.
8. 클라이언트 그래프에서 `src/server` import는 실패한다.
9. `src/shared/protocol.ts` 소스에는 공격력 기반값 10, 간격 기반값 800, 적 체력 30이 없다.

화면 확인:

1. `(pointer: coarse)`에서 왼쪽 아래 조이스틱을 밀면 서버 스냅샷의 플레이어가 그쪽으로 움직이고, 페이지는 스크롤되지 않는다.
2. 조이스틱을 놓으면 플레이어가 멈춘다.
3. 키보드만 있는 환경에서 조이스틱은 보이지 않고, WASD와 방향키로 이동한다. 반대 키를 같이 누르면 그 축은 멈추고, 페이지는 스크롤되지 않는다.
4. 카메라는 플레이어를 화면 중앙에 둔다.
5. 시작 실패 문구가 나올 때 전장에 플레이어 원이 없다.
6. 좁은 세로 화면과 넓은 가로 화면에서 일시정지 버튼과 체력, 경험치, 생존 시각이 안전 영역 안에 보인다.

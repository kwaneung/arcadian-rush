# 04 한 판의 끝

상태: 리뷰 전. 잠기기 전에는 구현하지 않는다.

## 목적

서버 페이즈로 일시정지하고, 사망과 제한 시간과 끊김에서 판을 끝낸 뒤 결과 화면을 보여 준다.

## 입력

- `pause`, `resume`, `Escape`
- 계약의 벽시계 270000ms
- 슬라이스 2의 사망
- 소켓 닫힘

## 규칙

- `playing`에서만 일시정지된다. `paused`에서만 재개된다. `choosing`에서는 둘 다 무시한다.
- 일시정지 동안 `simMs`, 적, 투사체, 획득, 체력은 그대로다. 벽시계는 흐른다.
- 벽시계 270000ms에 닿으면 페이즈와 상관없이 `time_limit`으로 끝난다. 끝난 뒤의 생존 시간 표시와 저장 값은 그때의 `simMs`다.
- 결과 화면의 생존 시간, 처치 수, 레벨, 이유는 종료 스냅샷의 `result`다.
- 메모리 저장소에서는 `recorded`가 거짓이다. 결과 화면에 `기록되지 않음`을 보여 준다.
- 종료 스냅샷 없이 소켓이 닫히면 마지막 HUD 숫자를 결과로 옮기지 않고 `연결이 끊겼습니다`만 보여 준다.
- 종료 뒤에는 같은 토큰으로 소켓을 다시 열 수 없다. 시작 버튼으로 새 발급만 가능하다.
- 일시정지 버튼은 이 슬라이스에서 활성이다. 문구와 `Escape` 동작은 계약을 따른다.

## 완료 조건

자동 테스트:

1. `playing`에서 `pause` 한 번이면 페이즈가 `paused`다. 그 상태로 `step`을 호출해도 `simMs`와 적 좌표와 체력이 같다.
2. `resume`이면 다시 `playing`이고 다음 틱의 `simMs`가 50 증가한다.
3. `choosing`에서 `pause`와 `resume`는 후보와 페이즈를 유지한다.
4. `now - 1000`보다 큰 일시정지 시각이 4개면 다음 `pause` 또는 `resume`는 페이즈를 바꾸지 않는다.
5. `now - activatedAt >= 270000`인 `step`은 `simMs`를 올리지 않고 `time_limit`이다. 첫 `step`이 `activatedAt + 50`이고 50ms마다 `playing`이었다면 종료 시점의 `simMs`는 269950이고 화면의 생존 시각은 `04:29`다. 그 직전까지 일시정지했다면 `simMs`는 일시정지 전에 쌓인 값이다.
6. `choosing` 중에 벽시계가 270000ms에 닿으면 `time_limit`이고, 아직 고르지 않은 후보의 등급은 오르지 않는다. 레벨 값은 후보가 열릴 때 이미 오른 값이다.
7. 사망 종료의 `result.reason`은 `death`이고 `simMs`와 `kills`와 `level`은 그 상태의 값이다.
8. `finish`를 두 번 호출하면 두 번째는 `unrecorded`다.
9. 소켓 닫힘 처리는 `disconnect`로 `finish`를 호출하고, 같은 `runId`의 `activate`는 다시 성공하지 않는다.

화면 확인:

1. 일시정지 버튼이 세로 화면과 가로 화면에서 항상 보이고, 누르면 적과 생존 시각이 멈춘다. `계속`을 누르면 다시 흐른다.
2. `Escape`는 버튼과 같게 동작하고, 카드가 떠 있을 때는 카드를 닫지 않는다.
3. 사망과 제한 시간의 결과 화면에 스냅샷과 같은 생존 시간, 처치 수, 레벨, 이유 문구가 있다.
4. 메모리 저장소의 결과에는 `기록되지 않음`이 있다.
5. 연결을 강제로 끊으면 직전 생존 시각이 결과 숫자로 남아 있지 않다.
6. 결과 화면의 시작으로 새 판을 열 수 있고, 이전 적의 위치가 이어지지 않는다.
